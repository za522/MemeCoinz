# UI component decisions

Release 0.3.0 adopts no external UI package. The three-screen product needs familiar search, segmented selection, disclosures, tables, and local filtering; existing React, semantic HTML, and CSS can deliver these without adding runtime weight or a second visual language.

This release includes the runtime rewrite. A clean production build reduced the comparable client asset set from about 150,814 to 139,968 bytes gzip, including a 57.2% CSS reduction. The default Coins screen contains 34 elements inside `main`, and representative 1440, 768, 390, and 320 pixel checks showed no page-level horizontal overflow. No external UI runtime was added.

## Component intake

| Screen or control | Task or state | Candidates reviewed | Decision | Chosen source | Signature kept | A11y and responsive result | Performance result | Rejected options |
|---|---|---|---|---|---|---|---|---|
| Coins mint search | Submit one exact mint and understand result, empty, or error state | Native form; shadcn Command; Kokonut search/input patterns; beUI search | **Borrow** familiar structure, install nothing | Native HTML form with structural lessons from [shadcn Command](https://ui.shadcn.com/docs/components/command) and [Kokonut UI](https://kokonutui.com/docs) | Persistent label/value, explicit submit, stable status/result region, separate demo action | Native keyboard submission, labelled input, 44px targets, one-column phone layout | No package cost; included in the measured client reduction | Command palettes imply a large local catalogue and can hide exact-mint validation; richer animated search adds cost without helping one-address lookup |
| Coin report cutoff | Select one registered point-in-time cutoff | Native buttons; shadcn Tabs; beUI tabs; Rare UI navigation/progress patterns | **Borrow** segmented selection, install nothing | Existing buttons with tab/pressed semantics | Visible selected state, exact cutoff labels, one coordinated report update | Keyboard-operable buttons, visible focus, wrap/scroll without clipping, Reduced Motion safe | No package or runtime cost added | A tab package is unnecessary for five buttons; progress or stepped-playback effects would imply an event sequence rather than a decision cutoff |
| Report evidence detail | Reveal formulas, provenance, wallet evidence, narrative, and limitations | Native `details`; shadcn Accordion; beUI Accordion; Transitions.dev resize/reveal recipes | **Borrow** disclosure hierarchy, install nothing | Native `<details>`/`<summary>` | Clear summary, retained open state, exact content, no modal interruption | Built-in keyboard behavior, large summary target, linear mobile flow, Reduced Motion safe | No dependency; avoid re-keying the report | Motion-heavy accordion and blur/mask reveals add paint and focus risk without improving comprehension |
| Assessment change | Explain a cutoff/result state update | CSS; Motion; Transitions.dev text/tab transitions | **Reject install**; use a short CSS state transition only if needed | Existing CSS | Brief opacity/colour response, no travel or price-like animation | State remains immediate with motion disabled | No animation dependency; no performance claim until measured | Motion is unnecessary for a local 150–220ms update; signature transitions would add more spectacle than information |
| Data source ledger | Audit exact interfaces, status, coverage, credentials, and rights | Semantic table; Beautiful UI record/filter table; shadcn Table | **Borrow** scan order, install nothing | Semantic table with structural lessons from [Beautiful UI](https://www.beautifului.dev/) | Dense but explicit rows, status text, official links, responsive scroll region | Caption, headers, keyboard links, text status, labelled horizontal scroll at narrow widths | No package added; batch if source count approaches 100 | A generic data-grid adds interaction and bundle cost not justified by the small registry |
| Terminology appendix | Search and filter definitions without losing reading context | Native form/list; Beautiful UI filter patterns; shadcn Input/Toggle Group | **Borrow** filter structure, install nothing | Native form controls | Persistent query, visible result count, category selection, readable definitions | Labelled search, pressed-state filters, live count, linear phone reading | Local filtering only; batch if the glossary becomes very large | Command palette or modal search would hide definitions and complicate focus restoration |
| Historical/cohort charts | Compare real time history, distributions, and flows | Bklit line, funnel, scatter, Sankey, and candlestick components | **Defer** until the required real data shape exists | None | None yet | Not applicable until exact values and table alternatives exist | Avoids unused chart payload and fabricated visual evidence | A chart over one synthetic fixture would look authoritative without a real cohort or history |
| Visual QA process | Prevent drift from the forensic daylight system | Manual acceptance checks; VibeCurb critique/visual-diff discipline | **Borrow process**, no runtime install | [VibeCurb](https://github.com/Yu-369/VibeCurb) concepts | Reference extraction, representative viewport review, drift rejection | Includes keyboard, zoom, Reduced Motion, and long-state review | Process only; no runtime effect | VibeCurb's maximal layout prescriptions are not adopted because this product requires calm minimal composition |
| Hosting/platform | Continue the existing repository, Cloudflare bindings, and Sites deployment | Existing stack; Manus full-stack platform/API | **Reject** migration | Existing React/Vinext/Cloudflare/Sites stack | Existing ownership, bindings, source control, and deployment path | No behavior change | No migration or new SaaS runtime | [Manus](https://manus.im/features/webapp) is a separate platform, not a component library; moving would expand scope and duplicate the current stack |

## Intake rule for future work

Before adopting an external component, record its exact product task, full visual/interaction signature, direct source and license, copied files and dependencies, truthful data mapping, keyboard/focus/touch/Reduced Motion behavior, responsive states, maximum DOM/paint cost, and before/after production measurements. If its full signature fails one hard gate, reject it instead of flattening it into an imitation.
