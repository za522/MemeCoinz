# UI component decisions

Release 0.5.0 adds a calculated historical-data view and descriptive association disclosure without installing an external UI runtime. Native tables, segmented buttons, and disclosures fit the task, preserve the established forensic-daylight language, and avoid implying causal or predictive certainty through decorative charts. The free collector, protected pipeline, and optional Telegram runner are operational interfaces, not a fourth product screen, browser setting, durable scheduler, or trading control.

The 0.3.0 production build is the comparison baseline. A clean 0.4.0 build on 28 August 2026 measured 143,844 bytes gzip across the comparable client assets (138,117 JavaScript + 5,727 CSS), 2.8% above the prior 139,968-byte baseline. The 0.4.1 hosted-feed recovery build measured 147,229 bytes gzip (141,521 JavaScript + 5,708 CSS), 5.2% above 0.3.0. These increases accompany real feed/report behavior and are recorded as costs, not described as improvements.

## Component intake

|---|---|---|---|---|---|---|---|---|

| Feed controls | Refresh and locally filter returned rows | Native form controls; shadcn Input/Select/Toggle Group; Kokonut search patterns | **Borrow structure; install nothing** | Native input, select, and buttons | Persistent values, explicit refresh, pressed/selected state, compact order | Labels, visible focus, touch-safe targets, wrapping toolbar | Local filtering only; automatic refresh must not re-key the table | Command palette and animated search hide the distinction between local ticker matching and exact-mint identity |

| Terminology appendix | Find a plain-English definition in context | Native search/filter; command palette; shadcn Input/Toggle Group | **Borrow filter structure; install nothing** | Native controls and definition list | Persistent query, result count, category selection | Labelled search, pressed filters, live count without focus theft | Local filtering only | Modal/command search hides definitions and complicates focus restoration |
| Historical/cohort charts | Compare price paths, distributions, relationships, and ablations | Bklit line/scatter/funnel/Sankey/candlestick components | **Defer** | None | None until a real cohort and exact chart question exist | Exact table alternative required before adoption | Avoids unused chart payload and fabricated visual authority | A chart over sparse live rows or an untrained model would make incomplete evidence look validated |
| Historical data columns | Switch between raw launch facts and chronology-safe calculated metadata/narrative features | Native segmented buttons; shadcn Toggle Group; data-grid column chooser | **Borrow segmented selection; install nothing** | Native buttons and semantic table | Basic/Calculated labels, preserved pagination, explicit feature subtext, unavailable values stay text | Keyboard/touch buttons, table headers, horizontal scroll and phone fallback | No grid runtime; only one column set renders | A generic column manager would hide the research taxonomy and add controls before the data warrants them |
| Cohort associations | Inspect which feature bands coincide with confirmed fast graduation | Native details/table; accordion; chart cards | **Use progressive disclosure; reject chart** | Native `<details>` with compact ranked rows | Denominator, confirmed count, lower-bound rate, no causal language | Built-in keyboard disclosure and linear mobile flow | No charting dependency | A visual ranking would overstate a censored descriptive relationship as model importance |
| Motion | Explain refresh, loading, and cutoff changes | CSS; Motion; Transitions.dev | **Reject install** | Existing CSS | Short colour/opacity feedback only | Reduced Motion keeps every state | No animation dependency | Price-like or ambient motion creates urgency and distracts from provenance |
| Visual QA | Detect drift from the forensic-daylight system | Manual acceptance checks; VibeCurb critique/visual-diff discipline | **Borrow process; no runtime install** | VibeCurb concepts | Reference viewports, long-state and overflow review | Includes keyboard, zoom, Reduced Motion, and source-error states | Process only | Maximal visual prescriptions do not fit a calm research product |
| Hosting/platform | Keep the existing React/Vinext/Cloudflare/Sites application | Existing stack; Manus platform/API | **Reject migration** | Existing stack | Current repository, bindings, source control, and deployment path | No behavior change | No migration/runtime duplication | Manus is a separate platform, not a component library, and would expand scope |

## Performance record

- Prior 0.3.0 comparable client assets: approximately 139,968 bytes gzip (135,076 JavaScript + 4,892 CSS).
- Prior 0.3.0 research-console chunk: approximately 24,015 bytes gzip.
- Release 0.4.0 comparable client assets: 143,844 bytes gzip (138,117 JavaScript + 5,727 CSS).
- Release 0.4.0 research-console chunk: 26,544 bytes gzip, up from 24,015 bytes.
- Release 0.4.1 comparable client assets: 147,229 bytes gzip (141,521 JavaScript + 5,708 CSS).
- Release 0.4.1 research-console chunk: 29,868 bytes gzip.
- Change versus the 0.3.0 comparable total: +3,876 bytes gzip (+2.8%).
- Structural gate: feed responses are capped at 100 rows; external images reserve dimensions and lazy-load; no chart, grid, animation, or component runtime was added.

## Intake rule for future work

Before adopting a component, record its exact task, full visual/interaction signature, source/license, copied files and dependencies, truthful data mapping, keyboard/focus/touch/Reduced Motion behavior, responsive states, DOM/paint cost, and before/after production measurements. If the full component fails one hard gate, reject it instead of flattening it into an imitation.
